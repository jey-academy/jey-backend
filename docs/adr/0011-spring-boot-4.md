# ADR-0011: Spring Boot 4.x 채택

- 상태: 채택
- 날짜: 2026-10-10

## 배경
초기 설계는 Spring Boot 3.x를 전제로 했다. 그런데 Spring Initializr로 골격을 생성한 시점(2026-10)의 기본값은 Boot 4.1.1 + Spring Modulith 2.1.1이었고, 골격도 그 버전으로 만들어졌다. 코드가 한 줄도 없는 지금 버전을 확정해야 한다.

## 선택지
1. Boot 3.x로 내린다 — 자료·예제가 많고 주변 라이브러리 호환이 검증됨 / 신규 프로젝트를 이전 메이저로 시작하게 되고, 운영 중에 메이저 업그레이드를 한 번 치러야 함
2. Boot 4.x로 간다 — 현재 메이저라 지원 기간이 길고 업그레이드 부담이 없음 / 3.x 기준 자료와 다른 부분이 있고, 일부 라이브러리는 호환 버전을 확인해야 함

## 결정
Spring Boot 4.x(현재 4.1.1) + Spring Modulith 2.x(현재 2.1.1)로 간다.

## 근거
- 마이그레이션할 기존 코드가 없어서 4.x로 시작하는 비용이 가장 낮은 시점이다.
- 1인 개발이라 운영 중 메이저 업그레이드는 부담이 크다. 처음부터 현재 메이저로 시작하는 편이 싸다.
- 실제 운영용이라 지원 기간이 긴 쪽이 유리하다.

## 포기한 것
- 3.x 기준으로 쓰인 블로그·예제를 그대로 따라 할 수 없다. 스타터가 기능별로 쪼개졌고(`spring-boot-starter-webmvc`, `spring-boot-starter-flyway`, 기능별 `-test` 스타터), 기본 JSON 라이브러리가 Jackson 3이다.
- 아직 추가하지 않은 springdoc-openapi, QueryDSL, WireMock은 도입할 때 Boot 4 / Jakarta 호환 버전인지 확인해야 한다.

## 재검토 조건
1차 범위에 꼭 필요한 라이브러리가 Boot 4를 지원하지 않고 대안도 없을 때.
