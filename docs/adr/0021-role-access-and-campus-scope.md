# ADR-0021: 역할별 접근 규칙과 지점 범위

- 상태: 채택
- 날짜: 2026-10-11

## 배경
로그인만 하면 역할과 무관하게 모든 API를 부를 수 있었다(ADR-0019는 "누구인가"까지만 다룬다).
역할은 셋이다. 관리자, 지점 데스크의 직원, 그리고 학원 밖에서 패스를 발급하는 연계 학원. 연계 학원 계정은 외부 사람이 쓰므로, 규칙을 빠뜨린 API가 하나라도 있으면 내부 자료가 밖으로 열린다.
지점은 여러 곳이다. 직원은 다른 지점의 자료도 보고 고칠 수 있어야 하지만, 돈과 관련된 자료는 소속 지점 것만 다뤄야 한다.

## 선택지
**역할 검사를 어디에 거는가**
1. 자체 애너테이션 + MVC 인터셉터 — 표시가 없으면 서버 시작을 막을 수 있음, 역할을 enum으로 적음 / 직접 만드는 코드가 생김, 컨트롤러 밖은 지키지 않음
2. Spring Security의 메서드 보안(`@PreAuthorize`) — 표준 기능 / 붙이지 않은 메서드는 열려 있음, 역할이 문자열
3. 보안 설정의 경로 규칙 — 한곳에 모임 / 기초 모듈이 다른 모듈의 주소를 알아야 함, 주소를 바꾸면 규칙이 빗나감

**지점 범위를 어떻게 거는가**
1. 로그인한 사용자에게 범위를 물어보는 메서드 — 필요한 자료에만 씀 / 부르는 것을 잊을 수 있음
2. ORM 필터로 모든 조회에 지점 조건 — 잊을 수 없음 / 직원이 다른 지점 자료를 봐야 하는 규칙과 어긋남, 단건 조회와 네이티브 쿼리에는 걸리지 않음

## 결정
역할 검사는 1번, 지점 범위는 1번을 채택한다.

**역할**
- 컨트롤러 메서드나 클래스에 셋 중 하나를 붙인다: `@AllowedRoles(역할들)`, `@AnyRole`(로그인한 누구나), `@PublicEndpoint`(로그인 없이).
- 메서드에 붙인 것이 클래스에 붙인 것보다 우선한다. 한 곳에는 하나만 붙인다.
- 서버를 시작할 때 모든 컨트롤러 메서드를 확인한다. 표시가 없거나 둘 이상이거나 역할이 비어 있으면 서버가 뜨지 않는다.
- 관리자도 적혀 있어야 통과한다. "관리자는 모든 기능"이라는 규칙은 두지 않는다.
- 역할이 맞지 않으면 403 `AUTH_ROLE_NOT_ALLOWED`. 로그인하지 않았으면 401이다.
- `@PublicEndpoint`는 표시일 뿐이다. 보안 설정의 허용 경로에도 있어야 열린다. 한쪽에만 있으면 401이다.
- 거부는 계정 ID, 요청 방식, 주소와 함께 로그에 남긴다.

**지점 범위**

| 역할 | 기본 | 소속 지점으로 묶은 자료 |
|---|---|---|
| 관리자 | 전 지점 | 전 지점 |
| 직원 | 전 지점 조회·변경 | 소속 지점만 |
| 연계 학원 | 다루지 못함 | 다루지 못함 |

- 소속 지점으로 묶는 자료는 수납, 수강료표, 패스 사용 내역이다. 늘릴 때는 이 문서를 고친다.
- 범위는 자동으로 걸리지 않는다. 묶은 자료를 다루는 기능이 로그인한 사용자에게 묻는다. 목록은 "화면이 고른 지점"을 넘겨 범위를 받고, 단건과 변경은 자료의 지점을 넘겨 확인한다.
- 직원이 지점을 고르지 않으면 소속 지점이다. 다른 지점을 고르면 소속 지점으로 바꿔 주지 않고 거부한다.
- 범위 밖이면 403 `AUTH_CAMPUS_NOT_ALLOWED`.

**연계 학원**
- 계정은 연계 학원 식별자를 가진다. 연계 학원 계정은 필수, 그 밖의 역할은 가질 수 없다.
- 연계 학원은 자기 식별자로 발급한 것만 다룬다. 남의 발급분에 접근하면 404로 답한다.

## 근거
- 가장 비싼 실수는 "규칙을 빠뜨린 API"다. 테스트로 찾는 방식은 테스트를 안 쓰면 못 찾는다. 서버가 뜨지 않게 하면 빠뜨린 채로 배포할 수 없다.
- 역할이 셋이고 API가 수십 개 규모라 표현식 언어까지는 필요 없다. enum 배열이면 충분하고 오타가 컴파일에서 걸린다.
- 지점은 두 곳이고 서로 존재를 안다. 범위 밖 자료를 404로 숨길 이유가 없고, 403이면 화면이 이유를 안내할 수 있다. 연계 학원은 서로 경쟁 관계일 수 있어 남의 패스가 있는지조차 알리지 않는다.
- 묶는 자료가 세 가지뿐이다. 모든 조회에 조건을 거는 장치는 예외를 푸는 설정이 더 많아진다.

## 포기한 것
- 컨트롤러를 거치지 않는 호출(이벤트 리스너, 배치)은 역할을 확인하지 않는다. 사용자의 요청이 아니므로 대상이 아니다.
- 지점 범위는 기능이 불러야 걸린다. 묶은 자료를 다루는 기능은 "다른 지점 직원이 403을 받는다"는 테스트를 가져야 한다.
- 로그인 정보는 로그인 시점의 값이다. 역할·지점·연계 학원을 바꾸면 그 계정의 세션을 끊어야 반영된다(ADR-0019).
- 로그인 정보에 필드가 늘어서, 배포 뒤 이전 세션 중 읽을 수 없는 것은 다시 로그인해야 한다.
- 지점 범위 거부는 로그에 남기지 않는다. 감사 로그를 만들 때 함께 다룬다.

## 재검토 조건
- 역할 말고 세부 권한(같은 직원인데 환불만 가능 등)이 필요해질 때 → 권한 단위 도입, 메서드 보안 검토
- 묶는 자료가 대부분이 될 때 → 자동으로 거는 방식 검토
- 지점 사이의 접근을 더 엄격히 나눠야 할 때(지점별 운영 주체가 달라지는 경우)
- 한 계정이 여러 지점이나 여러 연계 학원에 속해야 할 때
