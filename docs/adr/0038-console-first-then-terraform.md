# ADR-0038: 인프라는 콘솔로 먼저 만들고 기록을 남긴 뒤, 복구 훈련을 거쳐 Terraform으로 옮긴다

- 상태: 채택
- 날짜: 2026-10-18

## 배경
운영용 AWS 자원(망, 서버, DB, CDN, 계정 보안)을 처음 만든다. 운영 시작에는 기한이 있다. 만드는 사람은 한 명이고, 이 자원들을 직접 만들어 본 경험이 많지 않다.

인프라를 코드로 관리하면 같은 구조를 다시 만들 수 있고 바뀐 것을 리뷰할 수 있다. 다만 처음 만드는 자원을 코드로 쓰면, 각 설정이 무엇을 하는지 익히는 일과 코드 도구를 익히는 일이 겹친다.

## 선택지
1. 처음부터 Terraform — 재현성과 리뷰를 처음부터 / 설정과 도구를 동시에 익혀야 하고, 기한 안에 끝낼 위험이 커짐
2. 콘솔로 만들고 끝 — 가장 빠름 / 다시 만들 수 있는지 알 수 없고, 바뀐 것이 남지 않음
3. 콘솔로 만들며 구축 기록(만든 자원, 고른 값, 순서)을 남기고, 복구 훈련으로 다시 만드는 시간을 잰 뒤 Terraform으로 옮기고 다시 잰다 — 먼저 익히고 나중에 코드로 굳힘, 옮긴 효과를 숫자로 보임 / 옮기기 전까지는 기록과 실제가 어긋날 수 있음

## 결정
3번으로 한다.

- 자원은 콘솔로 만든다. 만드는 동안 구축 기록에 자원, 고른 값, 순서, 확인 결과, 걸린 시간을 적는다. 비밀값은 적지 않는다.
- 서버 안의 설정 파일(Nginx, NAT 인스턴스의 사용자 데이터, 배포 스크립트)은 처음부터 저장소에 둔다.
- 운영이 자리 잡으면 구축 기록대로 복구 훈련을 하고 다시 만드는 데 걸린 시간을 잰다.
- 그 뒤 Terraform으로 옮긴다. 지금 있는 자원은 `terraform import`로 가져오고, 상태는 원격 저장소에 잠금과 함께 두며, PR마다 CI가 `plan`을 보여 준다. 옮긴 뒤 같은 복구 훈련을 다시 하고 시간을 비교한다.

## 근거
- 기한 안에 운영을 시작하는 것이 먼저다. 처음 만드는 자원은 콘솔에서 설정 하나하나의 뜻을 보며 만드는 편이 실수가 적다.
- 구축 기록이 있으면 옮길 때 무엇을 가져와야 하는지가 정해져 있다.
- 복구 훈련을 옮기기 전과 뒤에 한 번씩 하면, 코드로 관리한 효과가 말이 아니라 숫자(다시 만드는 시간, 빠뜨린 설정의 수)로 남는다.
- 서버 안의 설정 파일은 콘솔과 상관없이 처음부터 저장소에 둘 수 있다.

## 포기한 것
- 옮기기 전까지는 자원의 변경이 리뷰를 거치지 않는다. 콘솔에서 바꾼 것은 구축 기록에 손으로 적는다.
- 옮길 때 `import`와 코드 맞추기에 품이 든다. 처음부터 코드로 쓰는 것보다 일이 한 번 더 있다.
- 기록과 실제가 어긋나면 첫 복구 훈련에서야 드러난다.

## 재검토 조건
- 자원을 자주 바꾸게 되어 손으로 적는 기록이 따라가지 못할 때 → 복구 훈련을 기다리지 않고 옮긴다
- 다른 사람이 인프라를 함께 다루게 될 때 → 옮기고 변경을 PR로 받는다
- 같은 구조의 환경(시험용 등)이 하나 더 필요해질 때 → 옮긴 코드로 만든다
