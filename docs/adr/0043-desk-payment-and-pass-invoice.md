# ADR-0043: 데스크 결제 — 받은 결과의 기록, 청구·결제의 상태, 패스 할인은 사용 기록에서만

- 상태: 채택
- 날짜: 2026-10-21

## 배경
수강료 청구(ADR-0042)에 결제를 붙인다. 데스크는 포스기 카드나 현금으로 받고, 앱은 결제를 하지 않는다. 온라인 결제(PG 승인, 웹훅, 대사)는 다음 단계다.

정할 것은 넷이다. 결제와 청구가 어떤 상태를 거치는지, 결제를 취소하면 청구는 어떻게 되는지, 같은 청구에 결제가 둘 생기지 않게 무엇이 막는지, 그리고 동탄고 패스 할인을 청구에 붙이는 길이다. 패스 할인은 직원이 고르는 다른 할인과 달리 근거(패스를 쓴 사실)가 있어야 한다.

## 선택지
**결제의 상태**
1. 받은 결과만 기록한다(완료 → 취소) — 데스크가 하는 일과 같다 / PG를 붙일 때 요청·승인 상태를 더한다
2. 처음부터 요청 → 승인 → 완료 — PG와 모양이 같다 / 데스크 기록에는 쓰지 않는 상태가 생긴다

**결제를 취소하면 청구는**
1. 다시 결제 전으로 돌아간다 — 다시 결제하거나 청구를 취소할 수 있다 / 결제 취소와 청구 취소가 따로다
2. 청구도 함께 취소된다 — 한 번에 끝난다 / 금액만 잘못 적은 경우에도 청구를 새로 만든다

**같은 청구의 결제 둘을 막는 것**
1. 청구 행 잠금 + 유효한 결제만 표시하는 유니크 키 — 동시 요청이 차례로 돌고, 마지막 방어선이 DB다 / 칸 하나(`open_key`)가 는다
2. 멱등 키만 — 단순하다 / 키가 다른 중복(두 번 누름, 두 직원)을 막지 못한다

**패스 할인을 붙이는 길**
1. 패스 사용 기록에서 청구를 만들고, 수납의 일반 청구 API는 그 할인을 받지 않는다 — 패스를 쓴 학생에게만 패스 번호와 함께 붙는다 / 경로가 하나 는다
2. 직원이 다른 할인처럼 고른다 — 단순하다 / 패스 없는 학생에게도 붙일 수 있고 근거가 남지 않는다

## 결정
결제는 1번, 결제 취소는 1번, 중복 방지는 1번, 패스 할인은 1번으로 한다.

- 청구: ISSUED →(결제) PAID →(결제 취소) ISSUED, ISSUED →(취소) CANCELED. 결제한 청구는 바로 취소하지 못한다(결제를 먼저 취소). 열린 청구는 ISSUED와 PAID다(결제한 달에 청구를 하나 더 만들 수 없다).
- 결제: COMPLETED →(취소) CANCELED. 수강료는 청구 합계와 같아야 한다(나눠 내기 없음). 교재비는 청구 계산과 따로 적는다. 결제 시각은 서버 시각이다.
- 청구 하나에 유효한 결제(COMPLETED)는 하나다. 취소한 결제는 기록으로 남는다. 결제·결제 취소·청구 취소는 청구 행을 먼저 잠근다.
- 결제 완료·취소는 수납 모듈의 도메인 이벤트로 낸다(장부 기록이 구독한다. 감사 로그도 이벤트로 남는다).
- 수납 모듈은 근거가 있는 할인을 받는 창구를 `api`에 둔다. 근거가 필요한 할인 코드는 설정으로 정하고(지금은 동탄고 패스), 직원이 고르는 일반 경로로는 붙지 않는다. 미리 계산은 된다. 수납 모듈은 그 코드가 무엇인지 모른다(동탄고 패스 모듈에 의존하지 않는다).
- 동탄고 패스 모듈이 사용 기록을 잠그고 그 창구를 부른다. 할인율은 지금의 패스 혜택, 참조값은 패스 번호다. 근거가 있는 할인은 직원이 고른 할인보다 먼저 계산한다. 사용 기록 하나에 열린 청구 하나이고, 청구를 취소하면 다시 만든다.
- 청구는 학생의 지금 지점에 속하므로, 직원은 사용 기록의 지점과 학생의 지금 지점을 모두 다룰 수 있어야 한다(사용 처리 뒤 학생이 지점을 옮겼으면 사용 기록의 지점 직원만으로는 만들지 못한다).

## 근거
- 데스크는 포스기에서 이미 승인된 결과를 받는다. 앱에서 요청·승인을 흉내 내면 상태만 늘고 지킬 규칙은 같다.
- 금액을 잘못 적은 결제는 결제만 취소하고 다시 적는 것이 흔하다. 청구까지 새로 만들면 장부와 감사 기록이 불필요하게 늘어난다.
- 멱등 키는 같은 키의 재전송만 막는다. "청구 하나에 결제 하나"는 업무 규칙이라 DB가 막는다.
- 패스 할인의 근거(패스 번호)가 청구에 남아야 장부에 "동탄고 패스 할인"을 적을 수 있고, 패스를 쓰지 않은 학생에게 붙는 것을 막을 수 있다.

## 포기한 것
- 수강료를 나눠 내거나 일부만 받는 경우는 받지 않는다.
- 결제 시각을 따로 적지 못한다(받은 직후에 기록한다).
- 패스 할인율은 청구를 만들 때의 혜택 값이라, 사용 처리와 청구 사이에 할인율을 바꾸면 바뀐 값이 붙는다.
- 환불 자체는 앱이 다루지 않는다(취소 기록만 남긴다).

## 재검토 조건
- 온라인 결제를 붙일 때 → 결제에 요청·승인 상태와 PG 참조를 더한다(데스크 기록은 그대로)
- 나눠 내기가 필요해질 때 → 청구 하나에 결제 여럿을 허용하고 합계로 PAID를 정한다
- 패스 이외의 근거 있는 할인(쿠폰 등)이 생길 때 → 설정의 코드 목록에 더하고, 그 할인을 준 모듈이 같은 창구를 부른다
