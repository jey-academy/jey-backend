# ADR-0047: 구글 시트 연동을 core 포트 뒤에 둔다

- 상태: 채택
- 날짜: 2026-10-23

## 배경
수납 모듈은 결제를 지점의 장부(구글 시트)에 쓴다(ADR-0044). 구글을 부르는 장치(시트 값 API 호출, 서비스 계정 서명, 장애·거절의 구분)는 수납 모듈 안에 있다. 이제 패스 모듈도 연계 학원의 시트에 기록을 남겨야 한다. 모듈은 다른 모듈의 `api`만 쓸 수 있고, 패스 모듈은 수납 모듈의 `api`를 쓸 수 있다(반대는 안 된다).

정할 것은 그 장치를 어디에 두는가다.

## 선택지
1. 기초 모듈의 하위 패키지(`core.sheets`)로 옮기고 `api`에 포트(읽기, 칸 쓰기, 줄 붙이기)와 오류 타입만 공개한다. 장부 규칙(어느 칸, 재시도 상태, 잠금)은 쓰는 모듈에 남긴다 — 외부 연동이 한 곳이고 알림(`NotificationSender`, ADR-0029)과 같은 모양이다 / 옮기는 일이 있다
2. 수납 모듈의 `api`로 공개한다 — 바로 쓸 수 있다(의존 방향이 맞다) / 수납 모듈이 업무와 무관한 범용 장치를 내보내고, 패스 모듈의 시트 쓰기가 수납 모듈의 변경에 묶인다
3. 패스 모듈에 같은 장치를 하나 더 만든다 — 모듈이 서로 독립이다 / 인증·장애 판정 코드가 둘이 되고, 고칠 때 한쪽을 빠뜨린다

## 결정
1번으로 한다.

- 포트는 `Spreadsheets`(`enabled`, `read`, `write`, `append`)이다. 구글 장애(시간 초과, 연결 끊김, 408, 5xx, 429)는 `SheetsUnavailable`(429의 기다릴 시간을 함께), 그 밖의 거절은 `SheetsRejected`(탭 없음, 권한 없음, 파일 없음, 그 밖)이다. 쓰는 모듈이 거절을 자기 미반영 이유로 바꾼다.
- 줄 붙이기는 표 끝에 줄을 끼워 넣는다(`INSERT_ROWS`). 붙인 줄 번호를 돌려준다. 결과를 모르는 실패 뒤에 같은 줄을 두 번 붙이지 않는 것은 쓰는 쪽의 일이다(먼저 읽어 본다).
- 설정은 `jey.sheets`(주소, 연결 5초·응답 15초까지의 시간 제한, 서비스 계정 키)다. 어느 파일에 쓸지는 쓰는 모듈의 설정이다. 키가 없으면 연결이 꺼진 채로 뜨고, 파일을 정했는데 키가 없으면 쓰는 모듈이 서버를 띄우지 않는다.
- 수납 모듈의 장부 동작은 바뀌지 않는다(시험의 기대도 그대로다).

## 근거
- 바깥 서비스를 부르는 일(인증, 시간 제한, 장애 판정)과 "무엇을 어디에 쓰는가"는 바뀌는 이유가 다르다. 앞의 것은 한 곳에서 고치고, 뒤의 것은 그 업무를 가진 모듈이 정한다.
- 기초 모듈은 업무 모듈 모두가 기대도 되는 자리다. 수납 모듈을 범용 장치의 주인으로 두면 "수납은 패스를 모른다"는 방향은 지켜도, 패스 기능이 수납 모듈의 공개 범위에 기대게 된다.
- 알림과 같은 모양이라 새 규칙을 배울 것이 없다.

## 포기한 것
- 옮기는 동안 설정 이름이 바뀐다(`jey.billing.ledger`의 주소·시간 제한·키 → `jey.sheets`). 운영의 환경 변수 이름은 그대로 두어 서버 설정을 고치지 않는다.
- 시간 제한의 상한은 수납 장부의 잠금 유지 시간에서 나온 값인데 이제 기초 모듈에 있다. 둘이 어긋나지 않는지는 사람이 본다.

## 재검토 조건
- 시트 말고 다른 문서 서비스로 옮길 때 → 포트는 두고 구현만 바꾼다
- 모듈마다 다른 구글 계정(키)이 필요해질 때 → 설정을 모듈별로 나눈다
