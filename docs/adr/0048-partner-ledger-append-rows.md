# ADR-0048: 연계 학원 장부는 기록마다 한 줄을 붙인다

- 상태: 채택
- 날짜: 2026-10-23

## 배경
연계 학원에도 자동으로 채워지는 구글 스프레드시트를 준다. 지점의 수납 장부(ADR-0044)와 달리 이 시트는 우리가 처음 만드는 것이라 기존 모양에 묶이지 않는다. 구글 시트를 읽고 쓰는 일은 기초 모듈의 포트로 한다(ADR-0047).

정할 것은 여섯이다. 무엇을 남기는지, 어떤 모양으로 쓰는지, 파일을 어떻게 정하는지, 같은 기록을 두 번 쓰지 않게 무엇이 막는지, 엉뚱한 파일에 쓰지 않게 무엇이 막는지, 못 쓰면 어떻게 하는지.

## 선택지
**무엇을 남기는가**
1. 두 방향 모두: 그 학원이 JEY 패스로 할인해 준 기록(원래 수강료·할인율·할인액·받을 금액)과, 그 학원이 발급한 패스가 JEY 지점에서 쓰인 기록 — 학원이 자기 일과 자기 패스의 결과를 한 파일에서 본다 / 줄의 모양이 둘이다
2. 할인해 준 기록만 — 줄이 한 모양이다 / 발급한 패스가 쓰였는지는 앱 화면에서 따로 봐야 한다

**어떤 모양으로**
1. 탭 하나(기본 `JEY 패스`)의 표 끝에 기록마다 한 줄을 붙인다(구분, 사용일, 학생, 패스 번호, 원래 수강료, 할인율, 할인액, 받을 금액, JEY 지점, 앱 표시) — 빈 줄을 찾을 필요가 없고 동시에 붙여도 겹치지 않는다 / 학원이 보기 좋게 다듬는 것은 학원 몫이다
2. 달마다 탭 — 달별로 나뉜다 / 탭을 미리 만들어야 하고 그 달 탭이 없으면 쓰지 못한다

**파일을 어떻게 정하는가**
1. 서버 설정(연계 학원 ID → 스프레드시트 ID) — 화면·API가 필요 없다 / 학원을 더하면 설정을 바꾸고 다시 띄운다
2. DB에 두고 관리자 화면에서 정한다 — 다시 띄우지 않는다 / API와 화면이 더 든다

**두 번 쓰지 않게**
1. 마지막 칸에 앱 표시(`앱:패스-{패스 ID}`)를 남기고, 붙이기 전에 탭을 읽어 표시가 있으면 그 줄로 끝낸다 — 붙이기는 됐는데 응답을 잃어도 다음 시도가 찾는다 / 시도마다 탭을 한 번 읽는다
2. 앱의 기록만 본다 — 단순하다 / 응답을 잃으면 두 번 붙인다

**엉뚱한 파일에 쓰지 않게**
1. 탭의 1행이 정한 머리글과 같을 때만 쓴다 — 설정의 ID를 잘못 넣어도 다른 문서를 망치지 않는다 / 학원이 머리글을 고치면 쓰지 못한다(미반영으로 보인다)
2. 확인하지 않는다 — 머리글을 자유롭게 고칠 수 있다 / 잘못 넣은 ID에 줄이 붙는다

**못 쓰면**
수납 장부(ADR-0044)와 같다: 패스 사용 처리는 그대로 두고, 패스마다 반영 상태 한 줄을 둔다. 구글 장애는 간격을 두고 다시 하고, 사람이 고칠 이유는 미반영으로 두어 관리자가 고친 뒤 다시 반영한다.

## 결정
무엇은 1번, 모양은 1번, 파일은 1번, 두 번 쓰지 않게는 1번, 엉뚱한 파일은 1번으로 한다.

- 패스는 한 번만 쓰이므로 패스가 기록의 열쇠다(반영 상태 줄도 패스마다 하나). 할인해 준 기록은 그 학원의 장부에, JEY에서 쓰인 기록은 패스를 발급한 학원의 장부에 쓴다.
- 패스 사용이 커밋된 뒤 이벤트 리스너가 바로 한 번 쓴다. 리스너는 트랜잭션 없이 돌고, 구글을 부르는 동안 DB 트랜잭션을 쥐지 않는다. 줄의 값은 시도할 때 사용 기록과 패스에서 읽는다(사용 기록은 고치지 않는다).
- 잠금은 두지 않는다. 구글이 줄을 끼워 넣으므로 서로 다른 기록은 겹치지 않고, 같은 기록은 반영 상태 행을 잠가 한 쪽만 맡는다.
- 구글 장애는 1분, 5분, 15분, 1시간, 3시간 뒤에 다시 하고 그다음 실패는 미반영이다. 설정 없음, 파일 없음, 탭 없음, 머리글 다름, 권한 없음, 그 밖의 거절, 앱 오류는 바로 미반영이다. 미반영 목록과 다시 반영은 관리자만 한다(연계 학원 계정은 자기 파일을 직접 본다).
- 값은 입력한 그대로 쓴다(금액은 숫자, 날짜·할인율은 글자). 전화번호는 싣지 않는다. 학생 이름은 연계 학원 사용 내역 화면에 이미 보이는 범위다. 쓸 때마다 감사 로그를 남긴다.
- 반영 상태의 규칙(맡기, 장애 간격, 오래 멈춘 시도)은 수납 장부와 같지만 코드를 함께 쓰지 않고 모듈마다 둔다. 두 곳이 다르게 자랄 수 있고(수납은 취소와 잠금이 있다), 공통으로 뺄지는 세 번째 쓰임이 생길 때 정한다.

## 근거
- 학원에게 필요한 것은 "우리가 몇 명을 얼마에 할인해 줬나"와 "우리 패스가 쓰였나"다. 둘 다 패스 사용에서 나오고, 한 파일에 있어야 따로 맞춰 보지 않는다.
- 우리가 만드는 시트라 빈 줄 찾기·탭 미리 만들기 같은 수납 장부의 제약을 지고 갈 이유가 없다. 붙이기는 동시성과 사람의 손에 가장 덜 흔들린다.
- 시범 학원은 하나이고 학원이 더해지는 일은 드물다. 그 한 번을 위해 API와 화면을 만들 근거가 아직 없다.
- 쓰기 요청이 닿았는데 응답만 잃는 경우는 앱의 기록으로는 알 수 없다. 시트에 남긴 표시만이 답이다(ADR-0044와 같다).
- 설정의 ID를 잘못 넣는 실수는 한 번이면 다른 문서를 망친다. 머리글 확인은 비용이 거의 없다.

## 포기한 것
- 학원이 1행 머리글을 고치면 앱이 쓰지 못한다(미반영으로 보이고 머리글을 되돌린 뒤 다시 반영한다).
- 학원을 더하면 서버 설정을 바꾸고 다시 띄워야 한다.
- 붙이기가 시간 초과로 끝났는데 구글이 다음 시도(1분 뒤)보다 늦게 반영하면 두 번 붙을 수 있다. 다음 시도까지의 간격으로 줄였을 뿐 없애지는 못했다.
- 탭은 관리자가 미리 만들어 둬야 한다(앱은 탭을 만들지 않는다).
- 반영 상태의 규칙이 두 모듈에 비슷하게 있다. 한쪽을 고칠 때 다른 쪽도 볼지 사람이 판단한다.

## 재검토 조건
- 연계 학원이 여럿으로 늘거나 자주 바뀔 때 → 파일 연결을 DB와 관리자 화면으로
- 장부를 쓰는 곳이 세 번째로 생길 때 → 반영 상태의 규칙을 공통으로
- 두 번 붙는 일이 실제로 생기면 → 붙인 뒤 다시 읽어 확인하고 중복 줄을 알림
