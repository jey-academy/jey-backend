# ADR-0049: 상품 이름은 화면에서만 "제이G패스"로 바꾸고 코드 이름은 둔다

- 상태: 채택
- 날짜: 2026-10-28

## 배경
학원이 할인 패스의 상품 이름을 "동탄고 패스"에서 "제이G패스"로 바꾸기로 했다. 패스의 규칙(발급, 확인, 사용, 할인)은 그대로다.

코드 이름 `dongtanpass`는 예전 상품 이름에서 왔다(ADR-0018). ADR-0018은 "동탄고가 아닌 다른 학교나 기관의 패스를 다루게 될 때" 이름을 다시 보라고 적었다. 그래서 화면 이름과 함께 코드 이름도 바꿀지 정해야 한다.

서버가 화면에 내보내는 상품 이름은 할인 유형 `DONGTAN_PASS`의 이름 하나다. 청구는 할인을 코드로 저장하고 이름은 보여 줄 때 읽는다.

## 선택지
1. 화면 이름만 바꾼다. 할인 유형의 이름, 명세 설명, 문서만 고친다. 코드 이름은 그대로 둔다 — 저장된 기록과 프론트와의 계약이 그대로다 / 코드 이름과 화면 이름이 다르다
2. 코드 이름까지 바꾼다(예: `jeygpass`). 패키지, 테이블 접두사, API 경로, 오류 코드, 이벤트·감사 행위·횟수 한도·알림 종류 이름, 설정 이름을 모두 바꾼다 — 이름이 하나로 맞는다 / 아래 근거의 비용이 든다

## 결정
1번을 채택한다.

- 화면에 보이는 이름은 "제이G패스"로 붙여 쓴다. 영문 표기는 두지 않는다. ADR-0018의 "한글 표기는 '동탄고 패스'로 띄어 쓴다"는 이 결정으로 바뀐다.
- 할인 유형 `DONGTAN_PASS`의 이름은 새 마이그레이션으로 바꾼다. 지난 청구서도 새 이름으로 보인다. 장부 시트에 이미 써진 줄은 고치지 않는다.
- 바꾸지 않는 이름:

| 종류 | 그대로 쓰는 이름 |
|---|---|
| 패키지, 모듈 | `com.jey.dongtanpass` |
| 테이블 접두사 | `dongtanpass_` |
| API 경로 | `/api/v1/dongtanpass/…` |
| 오류 코드 | `DONGTANPASS_*` |
| 할인 코드 | `DONGTAN_PASS` |
| 이벤트·감사 행위·횟수 한도·알림 종류 | `dongtanpass.{사건}`, `dongtanpass.{대상}` |
| 설정 키, 환경 변수 | `jey.dongtanpass.…`, `JEY_DONGTANPASS_…` |
| 클래스 이름, 커밋 scope | `Dongtanpass…`, `dongtanpass` |

- 모듈 설명(`package-info`)에 화면 이름과 코드 이름이 다르다는 것을 적는다.
- 앞선 ADR 본문의 상품 이름은 새 이름으로 고친다(ADR은 현재 규칙을 설명하는 문서다. ADR-0018과 같다). 파일 이름과 지난 PR·이슈·커밋 메시지는 고치지 않는다.

## 근거
- ADR-0018 때는 모듈에 선언 파일만 있어 이름을 바꾸는 비용이 가장 낮았다. 지금은 테이블 11개, 운영 데이터, 저장된 이벤트 발행 기록, 감사 로그, 프론트와의 계약(경로, 오류 코드)이 있다.
- 이벤트·감사 행위·횟수 한도·알림 종류의 이름은 한 번 쓰면 바꾸지 않는다. 이름을 바꾸면 감사 로그가 옛 이름과 새 이름으로 갈라진다. 미완료 이벤트 발행 기록은 옛 이벤트 이름으로는 되살리지 못해 계속 실패한다.
- 경로와 오류 코드를 바꾸면 프론트의 화면을 모두 다시 맞추고 두 저장소를 같이 배포해야 한다. 운영 설정의 환경 변수도 바꿔야 한다.
- 코드 이름은 사용자가 보지 않는다. 바꿔서 얻는 것은 개발자가 읽을 때의 일관성뿐이다.

## 포기한 것
- 코드 이름 `dongtanpass`와 화면 이름 "제이G패스"가 다르다. 처음 코드를 보는 사람은 둘이 같은 것인지 따로 알아야 한다(모듈 설명과 이 문서로 줄인다).
- 코드 이름에는 이제 상품과 맞지 않는 학교 이름이 남는다.

## 재검토 조건
- 코드 이름과 화면 이름이 달라 실제로 혼동이나 실수가 생길 때
- 패스를 다른 할인 상품과 함께 일반화하는 모듈로 다시 짤 때(그때 이름도 함께 정한다)
